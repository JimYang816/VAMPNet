# VAMPNet｜执行文档 04｜统一评估、结果持久化与增量重测

> 项目名称：**VAMPNet**。
> 文档版本：1.0。本文规定待实现的软件行为和验收条件，不包含已经测得的算法性能。
> 配套文档：[数据生成](01_仿真数据生成.md)、[baseline](02_Baseline算法实现.md)、[VAMP 深度展开](03_VAMP_DeepUnfolding实现.md)。
> 最高优先级：**有效的历史算法输出必须复用。绘图、表格、文档和可由已保存输出计算的统计分析，均不得触发均衡器重新推理。**

## 0. 不可违反的架构边界

将“测试”“比较”和“补齐缺失任务”分成三个模块，不允许用一个入口混合实现。

| 模块 | 可以做什么 | 明确禁止 |
|---|---|---|
| `evaluation` | 接受一个算法及其确定版本；检查缓存；仅对缺失输入推理；保存原始输出与指标 | 自动测试其他算法、自动训练、自动生成测试数据 |
| `comparison` | 读取指定版本的已完成结果；检查一致性；生成图表与分析 | 导入算法工厂、加载 checkpoint 做 forward、调用数据生成器、因缺文件自动重跑 |
| `orchestration` | 规划缺失任务；经显式执行选项，逐个调用需要的单算法评估；随后调用只读比较 | 将“新增一个算法”扩散成全部重测、隐藏 `force` 行为 |

`compare` 缺结果时返回具体缺失项和需要执行的命令，不能偷偷执行算法。用户希望的“有缓存则读取、没有则只跑该算法”由 `orchestration.ensure_results` 实现，而不是由绘图模块实现。

主调用关系固定为：

```text
sealed dataset + registered algorithm/checkpoint
                  ↓
            evaluation(one algorithm)
                  ↓
       immutable prediction artifacts
                  ↓
           metrics-from-predictions
                  ↓
           immutable metric artifacts
                  ↓
      comparison(read-only, no model imports)
                  ↓
             plots / tables / report
```

另设显式的 `benchmark(one algorithm, timing_profile)`，结果单独缓存。不能为了重画时间曲线重新计时。

### 1.2 测试输入一致性的真正判据

必须同时相同：

- `sample_id` 的有序全集与每个样本的接收输入内容哈希；
- 发送标签、数据/导频索引、符号映射与评价掩码；
- 轨迹编号、数据块编号、SNR 标签及其实际噪声实现；
- 数据版本、测试清单哈希、接收估计器和物理配置快照。

只检查“都使用 QPSK”“都取 20 dB”或“种子一样”不够。不能让四种算法各自调用数据生成器，即使给生成器传相同种子也不允许。

比较时禁止用内连接悄悄取四个结果的交集。任何算法少了一个正式样本，正式比较必须失败并列出差异；另做探索性子集报告时必须显式注册子集清单，并让所有算法使用该同一清单。

## 2. 指标的唯一数学定义

令 $\mathcal S_z$ 为 SNR 条件 $z$ 下冻结的样本集合。第 $s$ 个样本包含 $D_s$ 个未知数据符号、真实比特 $b_{s,i,j}$、真实符号 $x_{s,i}$、算法输出星座概率 $p_{s,i}(a)$。首版 $D_s=576$。

所有指标只统计数据子载波，排除导频、空载波、训练块和 CP。信道诊断另有定义，不混用该数据符号掩码。

### 2.1 BER：从比特边缘概率判决

由保存的对数星座概率得到

$$
L_{s,i,j}=\operatorname{LSE}_{a:b_j(a)=0}\log p_{s,i}(a)
-\operatorname{LSE}_{a:b_j(a)=1}\log p_{s,i}(a),
\qquad
\widehat b_{s,i,j}=\mathbf1\{L_{s,i,j}<0\}.
$$

保存逐样本整数：

$$
E_b(s)=\sum_{i=1}^{D_s}\sum_{j=1}^{2}\mathbf1\{\widehat b_{s,i,j}\ne b_{s,i,j}\},
\qquad N_b(s)=2D_s.
$$

汇总：

$$
\boxed{\operatorname{BER}_{\mathrm{preFEC}}(z)=
\frac{\sum_{s\in\mathcal S_z}E_b(s)}{\sum_{s\in\mathcal S_z}N_b(s)}}.
$$

不得先求各块 BER 再无权平均，以免在可变长度数据时改变口径。首版等长度时数值相同，仍统一使用计数汇总。

### 2.2 SER：从四类联合概率判决

$$
\widehat x_{s,i}=\arg\max_{a\in\mathcal A}p_{s,i}(a),
$$

$$
E_s(s)=\sum_i\mathbf1\{\widehat x_{s,i}\ne x_{s,i}\},
\qquad N_s(s)=D_s,
$$

$$
\boxed{\operatorname{SER}(z)=
\frac{\sum_{s\in\mathcal S_z}E_s(s)}{\sum_{s\in\mathcal S_z}N_s(s)}}.
$$

类别顺序固定为 `00,01,10,11`；概率相等时取最小类别索引。UDNet 的四类联合概率未必能分解成两个独立比特概率，因此“符号 MAP 的比特”不一定等于“比特边缘 MAP”。主 BER 与主 SER 分别采用上面的规定，禁止默认二者必须完全对应。需要 `BER_from_symbol_MAP` 时作为另一个有名字的指标，从保存概率重新计算。

### 2.3 均衡符号 NMSE：统一软输出口径

四种算法统一使用

$$
\widehat x^{\mathrm{soft}}_{s,i}=\sum_{a\in\mathcal A}a\,p_{s,i}(a).
$$

逐样本保存

$$
E_x(s)=\sum_i|\widehat x^{\mathrm{soft}}_{s,i}-x_{s,i}|^2,
\qquad P_x(s)=\sum_i|x_{s,i}|^2.
$$

$$
\boxed{\operatorname{NMSE}_{x,\mathrm{soft}}(z)=
\frac{\sum_{s\in\mathcal S_z}E_x(s)}{\sum_{s\in\mathcal S_z}P_x(s)}}.
$$

首版单位能量 QPSK 有 $P_x(s)=D_s$。若转成 dB，在汇总线性比值之后计算 $10\log_{10}(\operatorname{NMSE})$，不能平均逐样本 dB。

LMMSE 的原生线性输出 $\mathbf z$ 也保存为 `x_native`，可以另报 `NMSE_x_native`；不能把 LMMSE 的原生线性输出与其他三个算法的后验星座均值混在一个没有注明口径的 NMSE 列中。需要 EVM 时，可直接从同一误差能量得到 $\sqrt{\operatorname{NMSE}_{x,\mathrm{soft}}}$。

### 2.4 CSI NMSE：输入质量与算法输出分开

设 $\mathcal K$ 为活动发射子载波集合，保留所有接收行：

$$
E_H^{\mathrm{in}}(s)=\|[\widehat{\mathbf H}_s-\mathbf H_s^{\mathrm{true}}][:,\mathcal K]\|_F^2,
\quad
P_H(s)=\|\mathbf H_s^{\mathrm{true}}[:,\mathcal K]\|_F^2.
$$

$$
\operatorname{NMSE}_{H,\mathrm{input}}(z)=
\frac{\sum_s E_H^{\mathrm{in}}(s)}{\sum_s P_H(s)}.
$$

这是公共前端的诊断指标，四种算法的值应相同，不应把相同的输入 CSI NMSE 宣称成各均衡器改善信道估计的结果。

仅启用 `vamp_du/v1_refine` 等实际输出信道估计的版本时，另外报告

$$
\operatorname{NMSE}_{H,\mathrm{refined}}(z)=
\frac{\sum_s\|[\mathbf H_{T,s}-\mathbf H_s^{\mathrm{true}}][:,\mathcal K]\|_F^2}
{\sum_sP_H(s)}.
$$

保存最终总系数 $\mathbf c_T$ 和其基底引用即可重构 $\mathbf H_T$；不需要为了此指标保存每层全部稠密矩阵。没有信道细化的算法该列设为 `not_applicable`，不造数。

### 2.5 软比特与纠错译码指标

由未截断 LLR 可计算

$$
\operatorname{BCE}(z)=\frac{\sum_{s,i,j}
\operatorname{softplus}((2b_{s,i,j}-1)L_{s,i,j})}
{\sum_s2D_s}.
$$

LLR 分布、置信度可靠性、分组 BER、尾部误差统计等，都从已保存的逐符号输出计算，不能重新运行均衡器。

首版没有 FEC，`BER_post_FEC` 与信息块 `BLER` 必须记为 `not_applicable`。可以定义“数据 OFDM 块至少一个检测比特错误”的比例，但列名必须为 `data_block_detection_error_rate`，不冒充译码后的信息块错误率。

以后启用 FEC：在数据版本中固定编码器、码率、终止方式、交织和信息块边界；保存未截断 LLR。只改变外部译码器或 LLR 输出裁剪时，只做离线重新译码并形成新 `decoder_metrics_id`，不重新执行均衡器，前提是编码波形本身未变。编码波形改变则是新数据版本。

### 2.6 分组、配对统计与失败样本

同时给出 `SNR × regime` 分组结果和明确权重的全信道汇总。默认全信道汇总按实际数据量合并计数；若另用等海况权重，必须另命名。

置信区间以**独立轨迹为聚类单位**进行 bootstrap：每次抽轨迹，带入其全部数据块；比较算法时使用同一组抽样轨迹和同一 bootstrap 种子。跨 SNR 比较也保留同轨迹、同标准化噪声的配对关系。不能把高度相关的块或比特当成独立伯努利试验而给出过窄区间。

若零错误，保存真实计数 0 和样本量；对数图不能偷偷把 0 替换成一条“实测非零 BER”。可用明确的零错误标记；只有在独立试验单位确实成立时才给出相应零错误概率上界。bootstrap 全零区间不是“真实错误率必为零”的证据。

正式评估采用固定样本预算，不允许每个算法“累计 100 个错误就停止”，否则四种算法测试样本会不同。需要提高统计精度时，新增一个对所有算法一致的新测试清单，并按第 8 节增量补齐。

任何非有限输出、缺失输出或数值求解失败都必须落盘并使正式结果不完整；不能删掉这些样本再报告看似更好的 BER。处理失败策略的算法版本发生改变时，只重测该算法受影响的版本。

## 3. 运行时间、内存与复杂度

### 3.1 计时边界

每条记录区分：

| 字段 | 内容 | 纳入主均衡器时间 |
|---|---|---|
| `t_io_ns` | 从磁盘读取冻结数据 | 否，单列 |
| `t_shared_input_ns` | 将公共冻结描述解码为统一 $\widehat H,y,\widehat R_n$ | 单列，所有算法同口径 |
| `t_optional_feature_ns` | 该算法需要的 $B_q,C_0$ 特征重建/转换 | 是 |
| `t_prepare_ns` | 每个输入的 Gram、SVD、Cholesky、滑窗与白化准备 | 是 |
| `t_forward_ns` | 均衡迭代/网络层运算 | 是 |
| `t_soft_output_ns` | 公共输出接口需要的软解映射 | 是 |
| `t_transfer_ns` | CPU/GPU 数据传输 | 单列；是否计入端到端指标由配置固定 |

定义主等化时间

$$
t_{\mathrm{equalizer}}=t_{\mathrm{optional\ feature}}+t_{\mathrm{prepare}}
+t_{\mathrm{forward}}+t_{\mathrm{soft\ output}}.
$$

禁止排除传统 VAMP 每个新矩阵的分解，却包含其他算法的准备；也禁止把 DU 专用特征生成隐藏成“免费预处理”。公共 CSI 估计已在数据生成阶段完成，其耗时作为公共接收前端指标记录，不在性能比较时再次执行。

模型加载、GPU 上下文初始化、一次性预热不进入稳态延时，另报一次性启动成本。批处理吞吐量与单 OFDM 块延时是两个不同指标；首版主延时用 `batch_size=1`。

CPU 用 `time.perf_counter_ns()` 的前后差。GPU 运算具有异步行为，墙钟计时须在测量区间前后同步，或使用正确同步的设备事件；不能仅测 Python 发出调用的时间。[E1][E2]

### 3.2 第一次推理时间与专门基准时间分开

正式准确率推理保存每样本第一次执行时间，这样无需额外运行就有基本运行时间记录。为减少测量噪声，可以显式运行独立、一次性缓存的标准计时基准：

```yaml
schema_version: timing_v1
timing_profile_id: latency_cpu_or_gpu_v1
benchmark_manifest: configs/evaluation/benchmark_samples_v1.json
samples_per_regime_per_snr: 8
selection_seed: 62001
batch_size: 1
warmup_validation_samples: 8
repetitions_per_sample: 10
include_model_load: false
include_host_device_transfer: false
include_per_input_preparation: true
include_optional_features: true
synchronize_device: true
threads: 1
real_dtype: float64
complex_dtype: complex128
```

基准清单在看任何算法性能前固定，所有算法使用同一组样本；8 × 3 × 7 = 168 个输入。配置中的重复执行只属于明确的计时测量，不属于每次画图自动重跑。一旦此算法、版本和计时配置的基准结果完整，后续直接复用。

保存每次重复的原始时间，报告均值、中位数、P90/P95、吞吐量、峰值内存；不能只存一个平均值。测量期间不并发执行其他算法，不把不同硬件或不同线程配置的时间放在同一公平速度排名中。

### 3.3 硬件变化不应抹掉准确率历史

准确率预测记录包含原执行环境，是该历史实现的有效输出。换绘图电脑并不使 BER 失效。若要在新硬件上比较速度，只创建新的 `timing_profile_id`，对缺少该硬件计时的算法显式执行计时任务；既有准确率输出不重测。

如果要求验证“新数值后端是否产生相同预测”，这是新的部署验证任务，必须单独登记实现/数值环境签名。不能把旧输出冒充新平台已经验证的结果，也不能把这种验证隐含在普通比较命令中。[E3]

### 3.4 复杂度报告规则

设 $N$ 为接收维度，$D$ 为数据数，$T$ 为 VAMP 层数，$Q$ 为残差基数；UDNet 的窗口数 $J=N/W$，层数 $M$，隐藏宽度 $h$。

| 算法 | 参考复杂度，忽略常数 | 必须同时披露 |
|---|---|---|
| LMMSE | 白噪声时 $O(ND^2+D^3)$；一般稠密噪声还需白化 | 每输入分解、软解映射、工作内存 |
| 传统 VAMP | 固定矩阵预分解 $O(ND^2+D^3)$，后续约 $O(TD^2)$ | 迭代数、是否真正复用固定矩阵分解 |
| UDNet | 窗口 ZF 约 $O(JW^3)$，网络约 $O(JM(Wh+W^2))$ | 窗口宽度、边界与遗漏 ICI、所有训练参数 |
| VAMP-DU 核心 | 稠密基准约 $O(T[QN^2D+N^3+N^2D+ND^2+D^3])$ | $U_t$ 构造、每层变化的 $R_t$、精确迹、基底存储 |

DU 的 $U_t$ 均值项另有 $O(QN^2)$ 量级，表中以更高阶的方差项表示；实际优化后应记录真实算子计数，不能把上式当作精确 FLOPs。一般稠密 $\widehat R_n$ 的分解成本也必须计入相应算法。

`v1_refine` 额外报告 $Q\times Q$ 求解和构造 $G,d$ 的成本，不能只报 $O(Q^3)$ 而省略从大矩阵形成统计量的开销。参数量使用实际 `requires_grad` 元素总数；文档 03 核心版应为 119，规定的细化变体为 127。固定物理基、冻结估计器、模型内存和每样本工作内存分别报告。

## 4. 四层缓存，而不是一个混杂的大配置哈希

配置快照完整保留，但缓存按计算依赖拆分。

| 缓存层 | 产物 | 失效时需要做什么 |
|---|---|---|
| `prediction` | 每个样本的原始软输出 | 仅该算法的缺失预测需要 forward |
| `metrics` | 从预测及标签得到的误差计数和汇总 | 只读取保存的输出重新统计 |
| `timing` | 指定硬件、协议上的原始计时 | 仅显式补做该算法对应硬件基准 |
| `report` | 比较表、图与 Markdown | 只重新生成展示产物 |

### 4.1 不可变算法部署身份

定义规范化 JSON 函数 `canonical_json`：UTF-8、对象键排序、明确类型、有限数值、无无关空白；数组顺序保留。禁止用 Python `hash()`、文件修改时间或路径名代替内容哈希。

算法部署签名：

$$
K_{\mathrm{impl}}=\operatorname{SHA256}(\operatorname{canonical\_json}(
\text{algorithm\_name, algorithm\_version, math\_variant, dependency\_digest,}
\text{inference\_config, input/output\_contract, weight\_digest, numerical\_profile}
)).
$$

其中 `numerical_profile` 明确精度、推理所依赖的库/后端版本、确定性选项和必要的部署约束；不是读取当前绘图机环境后自动改写历史签名。版本注册时冻结该 profile。选择历史算法版本意味着选择其已登记的实现，而不是声称它已在当前机器重新运行。

`weight_digest` 对冻结推理权重按名字、shape、dtype、实际张量字节计算；完整 checkpoint 文件另有 `checkpoint_file_sha256` 用于审计。只移动文件位置，或仅改变 optimizer 容器信息而推理权重及结构未变，不要求重新推理。真正改变推理权重必须形成新部署身份。

人类可读的 `algorithm_version` 必须与一个部署身份一一绑定。已经登记的 `v1` 若代码内容变了，命令报错要求登记 `v2`，不能直接覆盖 `v1` 的原结果。

### 4.2 只哈希该算法真正依赖的代码

每个算法维护显式依赖清单，包括其传递依赖和共享函数：

```json
{
```

全仓库 Git commit、dirty 状态和环境锁文件都保存为溯源信息，但**全仓库 commit 不是所有算法共用的唯一失效键**。修改文档、绘图文件或 DU 专属代码，不影响 LMMSE/VAMP/UDNet 的部署签名。共享实际数值函数改变则应使所有确实依赖它的算法版本失效。

### 4.3 样本级预测键与整套测试键

对每个冻结样本定义

$$
K_{\mathrm{sample}}=\operatorname{SHA256}(K_{\mathrm{impl}},\ \text{sample\_id},\
\text{effective\_receiver\_input\_digest},\ \text{physical\_contract\_digest},\
\text{algorithm\_inference\_seed}).
$$

这里区分公共 `input_digest` 与算法实际使用字段组成的 `effective_input_digest`：前者对应文档 01 的 `input_sha256`，用于证明四算法接收信息相同；后者还按需绑定 `optional_features_sha256`，用于该算法的预测键。不能拿四个算法各自的有效输入键做相等比较。有效输入哈希覆盖影响 forward 的 $y,\widehat H,\widehat R_n$、索引/导频及该算法需要的附加字段，或覆盖它们的确定性存储表示和版本锁定的解码器。基底按 factorized exact 格式重建时，重建实现与资产哈希必须包含在签名中。

整套结果身份定义为

$$
K_{\mathrm{run}}=\operatorname{SHA256}(K_{\mathrm{impl}},\ \text{dataset\_version},\
\text{test\_set\_version},\ \text{ordered\_test\_manifest\_digest},\
\text{channel/modulation/OFDM/SNR\_config\_digests},\ \{K_{\mathrm{sample}}\}).
$$

测试集变了，旧整套结果不会被伪装成新结果；但如果新清单中某些样本的输入内容和样本预测键完全未变，可以引用这些已验证的逐样本输出，只为新增或变化样本计算。这是增量复用，不是忽略测试版本。

### 4.4 指标、计时与报告键

$$
K_{\mathrm{metric}}=\operatorname{SHA256}(
\text{prediction\_manifest\_digest},\text{labels/truth\_digest},
\text{decision\_config},\text{metric\_config},\text{metric\_code\_digest}).
$$

改变 BER 口径、分组方式、bootstrap 参数或软输出 NMSE 定义，先检查是否可以从已保存概率、均值、标签计算。可以则只形成新 `metric_id`。标签修正但接收输入未变，也首先只使指标层失效，不能默认重新均衡。

$$
K_{\mathrm{timing}}=\operatorname{SHA256}(K_{\mathrm{impl}},
\text{benchmark\_manifest\_digest},\text{hardware\_fingerprint},
\text{runtime\_environment},\text{timing\_protocol}).
$$

$$
K_{\mathrm{report}}=\operatorname{SHA256}(
\text{selected\_metric/timing\_ids},\text{comparison\_spec},\text{plot/table\_style}).
$$

`result_timestamp` 必须记录真实结果创建时间，但**不能加入用于判断同一次计算能否复用的键**。否则每次时间变了都会使缓存无效。图表样式只能影响 `K_report`。

### 5.3 逐样本原始输出

每个原始分片至少保存：

| 字段 | 类型/shape | 用途 |
|---|---|---|
| `sample_id`, `prediction_key`, `input_digest`, `effective_input_digest` | 字符串 | 公共输入配对与算法相关缓存分别验证 |
| `trajectory_id`, `block_id`, `snr_id`, `regime` | 元信息 | 配对比较和分组；不反馈给 forward |
| `data_idx` 或其固定资产引用 | $[D]$ | 确定符号对应位置 |
| `log_probs` | float64 $[D,4]$ | 必存；重新计算判决、LLR 和新统计 |
| `x_soft` | complex128 $[D]$ | 必存；直接均衡质量分析 |
| `llr_raw` | float64 $[D,2]$ | 必存；未裁剪的软信息与离线译码 |
| `x_native` | 可选 complex128 $[D]$ | 原生 LMMSE 等输出 |
| `c_final`, `C_final` | 细化版需要，$[Q]$/$[Q,Q]$ | 不重推理即可分析最终内部信道 |
| `basis_ref` | 可选不可变资产/估计状态引用 | 重建最终信道 |
| `actual_iterations`, `projection_counts`, `numerical_status` | 结构化值 | 数值与复杂度诊断 |
| 首次推理分段时间 | int64 ns | 基本时间记录 |

逐样本指标文件另保存 `bit_error_count`、`symbol_error_count`、`total_bit_count`、`total_symbol_count`、`squared_error_x`、`energy_x`、`squared_error_H_input`、`energy_H_true`、`bit_cross_entropy_sum` 和所有身份字段。

计数使用 int64；没有合适计数的指标用明确的分子/分母，不仅保存浮点比值。每个 SNR 的 CSV 至少同时有错误计数、总数、BER、SER、NMSE、时间、覆盖样本数和结果身份。

标签不必复制到每个算法目录，但其只读来源和哈希必须保存。NPZ 不允许 object/pickle，读取时 `allow_pickle=False`。序列化只用于无损保留；不能为了节省存储把概率量化为导致新硬判决变化的格式。

不要求保存所有层的 $N\times N$ 中间矩阵。若未来明确需要层间收敛曲线，可以在正式运行前指定小型诊断样本清单并保存相应中间状态；事后缺少这些状态时，只对所需算法和诊断样本进行明确登记的额外诊断，不触发四算法全套重测。

## 6. 事务、完整性与断点恢复

### 6.1 状态机

```text
MISSING → PLANNED → RUNNING → PARTIAL → COMPLETE
                         ↘ FAILED / CORRUPT
```

`COMPLETE` 必须意味着预期样本全部存在、身份相符、无重复、形状正确、输出有效、原始分片哈希正确。目录存在、`summary.json` 存在或最后一个样本编号很大，都不能作为完成判据。

### 6.2 一次单算法评估的严格顺序

1. 读取封存测试清单并校验 `SEALED.json`。禁止生成缺失数据；数据不存在就报错。
2. 解析算法的不可变部署身份与 checkpoint 引用；checkpoint 缺失就报错，禁止自动训练。
3. **在加载模型、初始化 GPU、读取大矩阵之前**检查预测缓存、指标缓存和覆盖范围。
4. 缓存有效时返回已完成产物引用；没有任何 forward。
5. 存在缺失预测时，先确认执行环境满足登记的数值 profile；未完成实验不能跨不同后端悄悄混合新旧输出，不兼容时登记独立部署验证任务。随后对 `prediction_run_id` 获取排他锁；获取锁后再检查一次，避免两个进程重复执行同一任务。
6. 根据已提交的 `prediction_index` 计算缺失样本键；模型只为这些样本加载一次并执行。
7. 每 16 个样本形成分片：先写临时文件，刷新并 `fsync`，计算内容哈希，使用同文件系统原子重命名提交；随后提交对应索引和进度。
8. 恢复时仅接受已原子提交且哈希有效的分片。最后一个未提交分片可以重算；此前已经持久化成功的样本不得再次 forward。
9. 全部预测完成后，按唯一 `sample_id` 重建指标统计；禁止恢复时把已计数分片再次累加。
10. 核验所有预期样本，最后原子写入 `COMPLETE.json`，释放锁。

指标文件与计时文件也采用各自的临时写入、校验和完成标记。索引数据库可以从 manifest 重建，数据库丢失不意味着预测输出丢失，更不意味着必须重新推理。

持久化“立即保存”的工程含义是持续提交小分片，并在单算法完成后立即封存其完整结果；不把四种算法结果都留在内存，等全部完成才统一保存。

### 6.3 缓存验证返回结构

```python
    missing_sample_keys=[...],
```

## 7. 可直接落实的调用伪代码

以下为待实现接口的行为定义，不是声称项目代码已经存在。

### 7.1 `evaluation`：单算法、先查缓存后加载模型

```python
def evaluate_one(algorithm_ref, suite, store):
    test = load_and_verify_sealed_test_manifest(suite)
    impl = resolve_registered_implementation(algorithm_ref)
    request = build_prediction_request(impl, test, suite.prediction)
    decision = store.inspect(request)

    if decision.prediction_status == "HIT":
        predictions = store.open_verified_predictions(request)
    else:
        with store.exclusive_lock(request.run_id):
            decision = store.inspect(request)  # 防止并发重复
            if decision.prediction_status == "HIT":
                predictions = store.open_verified_predictions(request)
            else:
                missing = plan_missing_or_invalid_samples(request, decision)
                # 所有可复用输出引用到新清单，不调用 forward。
                writer = store.begin_or_resume(request, immutable=True)
                writer.attach_verified_reusable_records(decision)
                if missing:
                    model = load_exact_model(impl)  # 只有这里加载算法
                    model.set_inference_mode()
                    for sample_ref in missing:
                        inp = load_receiver_input_only(sample_ref)
                        model.reset_sample_state()
                        output, timing = run_one_input(model, inp)
                        validate_equalizer_output(output, inp)
                        writer.append(output, timing, sample_ref)
                        writer.commit_if_full()
                    writer.commit_remaining()
                predictions = writer.seal_after_exact_coverage_check(test)

    # 指标修改、汇总缺失也只读已保存输出。
    metrics = ensure_metrics_from_saved_predictions(
        predictions=predictions,
        labels=load_labels_by_verified_reference(test),
        metric_config=suite.metrics,
        store=store,
    )
    return EvaluationArtifacts(predictions=predictions, metrics=metrics)
```

`run_one_input` 不能调用数据生成、训练或其他算法。一个样本的 online 系数状态必须重置，不能从另一个测试样本残留；需要顺序跟踪的未来算法应另定义序列输入与缓存键，不能偷偷改变首版块独立协议。

### 7.2 `comparison`：严格只读

```python
def compare_saved_results(spec, read_only_store):
    artifacts = [read_only_store.resolve_exact(ref) for ref in spec.algorithms]
    verify_all_complete(artifacts)
    verify_identical_sample_ids_and_input_digests(artifacts)
    verify_identical_labels_and_metric_definitions(artifacts)
    verify_timing_profiles_or_mark_not_comparable(artifacts)
    table = assemble_from_saved_metric_artifacts(artifacts, spec.groups)
    return write_report_and_figures(table, spec.presentation)
```

此模块不得 import `vampnet.algorithms`、`vampnet.training` 或 `vampnet.channel.generator`。指标文件缺失时输出 `recompute_metrics` 命令，不能通过调用 `evaluate_all` 补齐。

### 7.3 `orchestration`：只补必要任务

```python
def ensure_results_then_compare(spec, execute_missing=False):
    plan = build_dependency_aware_plan(spec)  # 不加载模型
    print_plan(plan)
    if not execute_missing:
        return plan
    for task in plan.tasks:
        if task.kind == "PREDICT_MISSING_ONE_ALGORITHM":
            evaluate_one(task.algorithm_ref, task.suite, store)
        elif task.kind == "RECOMPUTE_METRICS":
            recompute_metrics_from_saved_outputs(task)
        elif task.kind == "BENCHMARK_MISSING_PROFILE":
            benchmark_one_explicitly_requested_algorithm(task)
        else:
            assert task.kind == "CACHE_HIT"
    return compare_saved_results(spec, read_only_store)
```

默认只打印计划；`--execute-missing` 才执行已列明的任务。没有“比较前先全部评估”的步骤。

## 8. 失效、复用与新增实验的决策表

| 改变 | 原始预测是否需要重新执行 | 正确动作 |
|---|---|---|
| 只改 BER 图颜色、坐标、图例 | 否 | 新 report，复用 metrics/predictions |
| 改表格、Markdown、论文文字 | 否 | 仅展示文件变化 |
| 只修改 DU 数学或推理代码 | 仅 DU 新部署版本 | baseline 历史输出和计时保持有效 |
| DU checkpoint 实际权重改变 | 仅该 DU checkpoint | 新版本/新部署键，独立保存 |
| checkpoint 仅路径移动 | 否 | 验证权重和文件内容身份，不按路径失效 |
| 训练脚本变化，但选择的 checkpoint 和推理实现未变 | 否 | 保存训练溯源，不伪造推理变化 |
| 新增第五种算法 | 仅新算法 | 原四种算法直接读取 |
| 新增可由 `log_probs/x_soft` 得到的统计 | 否 | 新 metric，不加载均衡器 |
| BER/SER 判决口径修正 | 已有完整概率时否 | 从概率重算所有参与结果的该指标 |
| 输出需要新的、此前未保存且无法推导的中间状态 | 仅需要该状态的算法/样本 | 单独诊断任务或新输出契约；不可全算法默认重跑 |
| SNR 只取既有集合的子集 | 否 | 显式子集 view，所有算法相同 IDs |
| SNR 新增 35 dB | 旧 0～30 dB 预测不重跑 | 新测试清单，逐算法只补新增 35 dB 样本 |
| 测试轨迹新增，旧样本完全未变 | 旧样本不重跑 | 新版本复用旧样本键并补新样本 |
| 信道参数、噪声波形、OFDM/QPSK 或接收输入改变 | 对变化样本需要 | 建新数据/测试版本；仅对请求算法补缺失键 |
| 只修正标签，输入波形没有变化 | 否 | 新标签哈希、新指标；审计修正原因 |
| 外部译码器/LLR 裁剪变化，已有原始 LLR | 否 | 只重新译码、统计 |
| 当前机器更换，仅加载历史 BER | 否 | 保留历史执行环境标记 |
| 要比较新硬件速度 | 不重跑完整准确率 | 显式补对应 timing profile |
| 某个原始分片损坏 | 仅该算法受损样本 | 先尝试恢复/备份，再显式修复缺失部分 |
| 某个汇总 CSV 被删除 | 否 | 从原始输出重建指标 |
| 共享实际数值函数改变 | 仅依赖该函数的算法 | 各自登记新实现，不影响无关算法 |

新 SNR、新轨迹会改变整套测试身份，因此必须生成新的完整结果清单；不能在旧 `COMPLETE` 目录中追加几行后仍声称是原测试版本。复用允许发生在可验证的样本粒度，不能仅凭“看起来是同一个场景”。

```bash
python -m vampnet.cli.evaluate --algorithm lmmse  --version v1 --suite configs/evaluation/accuracy_v1.yaml
python -m vampnet.cli.evaluate --algorithm vamp   --version v1 --suite configs/evaluation/accuracy_v1.yaml
python -m vampnet.cli.evaluate --algorithm udnet  --version v1 --suite configs/evaluation/accuracy_v1.yaml
python -m vampnet.cli.evaluate --algorithm vamp_du --version v1 --suite configs/evaluation/accuracy_v1.yaml
python -m vampnet.cli.compare --spec configs/comparison/v1_all.yaml
```

每一行 `evaluate` 成功就单独封存，不等待其他算法。再次执行这些相同命令时应全部返回 `CACHE_HIT`，而非再次测试。

也可使用：

```bash
# 只展示计划：缺哪个就列哪个；没有 forward
python -m vampnet.cli.ensure_results --spec configs/comparison/v1_all.yaml

# 显式执行计划中的缺失任务
python -m vampnet.cli.ensure_results --spec configs/comparison/v1_all.yaml --execute-missing
```

### 9.3 只修改 DU 得到 v2

先按文档 03 登记和训练 DU v2；不改测试集。复制比较配置，仅将 DU 的版本从 v1 改为 v2，保存为 `v2_vs_baselines.yaml`。

```bash
python -m vampnet.cli.evaluate --algorithm vamp_du --version v2 --suite configs/evaluation/accuracy_v1.yaml
python -m vampnet.cli.compare --spec configs/comparison/v2_vs_baselines.yaml
```

预期执行计划：

```text
lmmse/v1  → CACHE_HIT, new_forward_samples=0
vamp/v1   → CACHE_HIT, new_forward_samples=0
udnet/v1  → CACHE_HIT, new_forward_samples=0
vamp_du/v2→ PREDICT_MISSING, new_forward_samples=10080
comparison→ LOAD_SAVED_RESULTS_ONLY
```

这是必须由自动化测试保证的行为，不是日志里的口头承诺。

### 9.4 只改图、增加指标或缺失时间结果

```bash
# 改图样式后，只读结果绘图
python -m vampnet.cli.compare --spec configs/comparison/v2_vs_baselines.yaml

# 新指标由既有概率与均值计算，不执行网络
python -m vampnet.cli.recompute_metrics --prediction-run RUN_ID --config configs/evaluation/metrics_v2.yaml

# 需要专门计时，显式指定一个算法；已有相同计时则命中缓存
python -m vampnet.cli.benchmark --algorithm vamp_du --version v2 --profile configs/evaluation/timing_v1.yaml
```

不得提供默认重新执行四算法的 `compare_all.py`，不得在比较命令中隐藏 `--force`，不得为了输出新时间戳而重算旧预测。

## 10. 与前面三份文档的依赖衔接

| 上游变更 | 缓存处理 |
|---|---|
| 文档 01：实际修改生成器/估计器并重新生成不同字节的数据 | 新数据版本和测试清单；旧实验保留，不能覆盖 |
| 文档 01：仅增加说明、修改非执行文档 | 数据与结果均不失效 |
| 文档 02：仅修改 UDNet 网络或窗口 | 只新增 UDNet 版本；LMMSE、传统 VAMP、DU 历史输出复用 |
| 文档 03：仅修改 DU 温度、层数、参数训练结果 | 只新增 DU 部署身份并推理 |
| 文档 03：从核心版切换细化版 | 显式 `math_variant`/版本改变，仅运行该变体 |
| 文档 04：指标实现修正而原始输出完整 | 只重算相应 metrics，并重新比较 |
| 文档 04：仅绘图程序更新 | 只产生新 report |

注意：长期反复查看同一个固定测试集并据此挑选算法，会使它逐渐成为开发反馈。模型选择和超参数调整必须依据固定验证集；固定测试集用于版本回归比较，不等于自动保证未偏倚的最终泛化结论。需要独立最终检验时另建预先封存的外部测试版本，四种算法按同一清单评价，旧实验不作废或删除。

## 11. 缓存机制必须通过的自动化测试

测试使用小型虚拟数据集与 `forward_spy` 计数器，不用正式 10080 样本反复验证缓存。每个执行计划记录 `model_load_count`、`forward_sample_count` 和 `reused_sample_count`。

| 测试编号 | 操作 | 验收条件 |
|---|---|---|
| CACHE-01 | 第一次四算法测试 | 各算法只执行其全部样本一次，并独立保存 |
| CACHE-02 | 原命令再执行一次 | 四算法 model_load/forward 均为 0 |
| CACHE-03 | 只修改绘图配置 | forward 为 0；只有 report_id 变化 |
| CACHE-04 | 只修改 Markdown/全仓 Git commit | 各算法部署依赖未变时全部命中 |
| CACHE-05 | 新 DU v2 | 只有 DU v2 发生 forward |
| CACHE-06 | DU 权重改变但错误沿用 v1 名字 | 拒绝覆盖，要求登记新版本 |
| CACHE-07 | 只移动 checkpoint 文件 | 身份未变则命中 |
| CACHE-08 | 新增可推导指标 | forward 为 0，仅 metric_id 变化 |
| CACHE-09 | 删除汇总 CSV | 从保存输出重建，forward 为 0 |
| CACHE-10 | 新增算法 | 原算法全部命中，只跑新增算法 |
| CACHE-11 | 运行到第 $k$ 个已提交样本后中断 | 恢复只运行未提交/缺失样本 |
| CACHE-12 | 同时启动同一算法同一键 | 锁与复查保证每个样本最多提交一次 |
| CACHE-13 | 一个 baseline 分片损坏 | 明确告警；只允许修复该算法受损样本 |
| CACHE-14 | 两套结果只有种子相同但噪声哈希不同 | 正式比较拒绝 |
| CACHE-15 | 算法缺一个样本 | 正式比较拒绝，不做隐式交集 |
| CACHE-16 | 新增一个 SNR，新清单保留旧样本 | 旧样本 forward 为 0，只补新增样本 |
| CACHE-17 | 只在已有 SNR 上绘制子集曲线 | forward 为 0 |
| CACHE-18 | 换硬件加载旧 BER | 只读正常；旧时间不冒充新硬件时间 |
| CACHE-19 | 新计时 profile | 只执行显式 benchmark，准确率预测不覆盖 |
| CACHE-20 | `comparison` 运行时禁止模型导入 | 用 import guard 确认任何算法加载都会导致测试失败 |
| CACHE-21 | 数据未 SEALED 或 checkpoint 不存在 | 报错，不生成数据、不训练模型 |
| CACHE-22 | bootstrap/分组规则改变 | 只重算 metric，使用保存的样本级计数 |
| CACHE-23 | 删除可重建 index.sqlite | 扫描 manifest 重建，forward 为 0 |
| CACHE-24 | 共享数值依赖变化 | 只使实际依赖该函数的部署版本失效 |

## 12. 实现顺序与最终交付验收

建议按以下顺序编写工程代码：

```text
输入/输出 schema 与规范化哈希
→ 算法独立依赖清单和不可变版本注册
→ 样本级原始输出写入、校验与原子提交
→ 断点恢复与并发锁
→ 纯函数指标计算
→ 单算法 evaluation
→ 严格只读 comparison
→ 增量 orchestration
→ 独立 timing 缓存
→ CACHE-01～24 验收
→ 才运行正式四算法测试
```

正式完成条件：相同测试清单、全部样本覆盖、原始输出和计数可追溯、各算法结果独立持久化、对比配置可重建、只修改一个算法时其他算法的 forward 计数严格为零。仅有四条 BER 曲线或一个 `results.csv` 不构成完成。

最终稳定工作流必须保持：

```text
固定测试集
→ 单算法首次测试并持久化
→ 四算法已有结果的只读比较
→ 修改其中一个算法、登记新版本
→ 只补该新版本的缺失测试
→ 保留其历史版本和其他算法结果
→ 从历史输出计算新统计
→ 只读绘图与分析
```
